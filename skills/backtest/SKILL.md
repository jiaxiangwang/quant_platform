# 回测

## 工作流

1. 检查策略代码已通过 Sandbox 的语法、导入、单元测试和未来函数检查。
2. 调用 `knowledge_search` 获取回测 SDK 的准确入口和结果字段，禁止臆造方法名。
3. 固化标的、样本区间、频率、初始资金、撮合、手续费、滑点、交易日历和数据版本。
4. 通过回测 Tool 提交任务；保存策略代码哈希、参数、SDK 版本和任务 ID。
5. 校验成交数量、异常日志、净值连续性、成本是否生效以及信号与成交的时间关系。
6. 输出收益、最大回撤、Calmar、胜率、盈亏比、频率、持仓时长和交易成本，并明确假设。
7. 结论为“回测验证通过/不通过/信息不足”，不能把历史回测等同于未来收益。

## 参数寻优

参数寻优必须使用训练/验证分离或 Walk-Forward。优先选择多组稳定参数，不以单次样本内最高收益作为唯一标准。
